# 2026-09-28

## 视频编辑器音轨波形「看着怪怪的」——根因与修复

排查发现是**两个叠加的 bug**，都用探针 + 离屏渲染实测确认过，不是猜的。

### 1. 波形提取：一秒一根针（主因）

`AudioWaveform.Extract` 按「一次 `ReadPcm` 读到的整块最大值」结算峰值，而读块是 1 秒
（192000 字节）＝ 50 个桶。桶循环里 `bucketPeak = 0` 清零，导致**整个读块的峰值只落在该块
的第一个桶里，后 49 个桶全是 0**。实测（6s 线性上升包络测试音频）：

| | 与期望包络平均误差 | 有声段最长「值不变」连续段 |
|---|---|---|
| 旧实现 | 0.5159 | ×（实际为首桶有值 + 49 个 0） |
| 新实现 | 0.0031 | 0 |

修法：**逐个采样**累加，满 `samplesPerBucket = OutSampleRate * 20ms * OutChannels` 才结算一桶。
`OutBytesPerSample` 是「一帧（含全部声道）」的字节数（4），不是单声道采样字节数（2），
按采样步进时要用 `OutBitsPerSample / 8 == 2`，别拿它当步长。

### 2. 音频块布局溢出（另一半原因）

`BuildClipBlock` 里音频块把 28px 波形**追加在两行文字下面**再塞进块：内容总高
15+2+14+2+28=61（+Margin 12=67），块高只有 `laneHeight(60)-12=48` → StackPanel 垂直居中后
波形被挤出块下缘（Border 不裁剪子元素，只被泳道裁）、名称文字被顶到块外。改成
`Grid(RowDefinitions="Auto,*")`：第一行横排「名称 + 起止/时长」，其余高度全给波形；
并在内容层加 `ClipToBounds`。

### 3. 顺带修掉的两处（同一族 bug：音频片段 `Track == -1`）

- 波形几何宽度原按 `clip.Duration * _pxPerSecond` 画，而画布比块窄 15px（Border 3 + Margin 12）
  → 右侧一截被裁。改为等布局完成后按 **画布实际 Bounds** 重画（挂 `SizeChanged`）。
- 音频块高度/泳道高度跟随：新增 `LaneOfClip(clip)`（音频走 `VideoLaneCount + AudioTrack`），
  `LaneHeightOfClip`，并修掉 `ResizeLane` 里 `clip.Track == track` 永远不匹配音频片段的问题。

### 4. 画法

`BuildWaveformVisual`（采样点用斜线相连 → 锯齿感）改为 `BuildWaveformGeometry`：每个像素列
一根竖条、列间垂直跳变，上下对称，静音段保留 0.75px 半高（视觉 1.5px 细线，波形不断开）。
配色随主题：浅色用深青绿 `(205,38,136,116)`（压在浅灰块上才看得清），深色用亮青绿
`(205,104,214,178)`。

### 验证方式（可复用）

- 探针：临时项目链接 `AudioWaveform.cs` + `FFmpegAudioDecoder.cs`，塞 `DiagnosticLog` /
  `FFmpegRuntime` 桩类；生成「已知包络（线性上升 + 一段静音）」的 WAV，断言逐桶误差 / 台阶长度 /
  静音值。旧算法**原样复刻**在探针里做对照（这是定位的关键，否则只能靠猜）。
- 视觉：把片段块的布局常量与几何算法 1:1 移植到 System.Drawing，按真实布局离屏画 PNG
  再肉眼看（GDI+ / Skia / Avalonia 对本例的单连通多边形填充等价）。已存成 skill
  `avalonia-offscreen-render-verify`。
- ⚠️ `deploy.ps1` 在 Windows PowerShell 5.1 下会因中文注释解析失败，必须 pwsh；本次直接用
  bash 复制产物（`rm -rf $PLUG/* && cp -r $OUT/* $PLUG/`），宿主未运行无需 Stop-Process。

### 上一轮遗留（本轮已全部修掉）

`MarqueeSelect` / `ClipAtTimelinePoint` / `BeginClipDrag` 里用 `clip.Track` 定位音频片段
（-1 → 位置算到最底部）→ 框选选不中音频片段、seek 线点不中音频片段、拖拽音频片段纵向不跟手。
本轮统一改走 `LaneOfClip` + `LaneVisualTop`。

## 时间轴拖拽「不跟手」根因（反复出现的那条）+ 两处体验优化

### 真凶：音频泳道被画在视频泳道**上方**，而所有按 Y 判定的模型辅助函数按「视频在上」写

两条独立证据：

1. **代码**：泳道网格用 `Grid.SetRow(lane, RowOfTrack(t, TotalLaneCount)) = TotalLane-1-t` →
   泳道号最大的音频泳道落到 row 0 = 最上面；而 `VisualTopOfTrack(track, TrackCount)` /
   `ResolveDropTarget(y, TrackCount)` / `ClipAtTimelinePoint` 全都假设「视频轨区从 y=0 开始」。
   于是**每一处 Y 判定都少算一个音频泳道高度（默认 60px）**。
2. **用户日志**（`video-editor.log` 17:20 那批）：`DRAG 按下 ... track=0 rootX=159 grabY=93`
   与同一按下的 `PRESS-ROOT x=159 y=99 hasClip=False` —— 按得中片段，同一坐标 `ClipAtTimelinePoint`
   却判定「此处无片段」→ 证明**画出来的泳道几何 ≠ 模型算的泳道几何**。
   （当时工程 `video-project.ciproj` = 2 视频轨 + 1 音频轨 → 视频轨 0 实际在 y=120，模型说 0。）

后果正好是用户描述的两件事：
- 抓取偏移按模型算 = `pressY − 6`，真实是 `pressY − 66` → **第一帧块就跳 60px，整场拖拽块与指针差一截**；
- 落点按 Y 判定整体偏一个泳道 → 指着「轨道 1」却落到别的轨 / 判成「新建轨道」。

**修法**：新增 `LaneOrder() / LaneAtRow(row) / RowOfLane(lane) / LaneVisualTop(lane)` 作为行号与
顶部坐标的唯一权威（视频在上 = 轨号大的在上，音频在下 = A1 最底），轨道头列、泳道网格、
`ResolveDropTarget`、`UpdateDropHighlight`、`BoundaryYOfInsert`、`MarqueeSelect`、
`ClipAtTimelinePoint`、`SetLaneHeight` 全部改走它。视频轨区回到 y=0 后，那些「按视频轨数反推行号」
的辅助函数反而全部自动正确。数值校验（V/A 组合 1+1、2+1、3+2）：泳道中点必命中自己、
视频泳道实际顶部 == 模型顶部、拖到视频区下方 = 视频区插入。

### 另外三条「不跟手」的独立成因（都已修）

1. **`SnapTime` 自吸附**：被拖片段的 StartTime 在拖动中实时变化，它自己的首/尾永远是吸附候选 →
   指针动 <8px 时片段**完全不动**，之后一跳一跳、永远落后一点。日志里 `dx=6px → start=0s` 即此。
   → `SnapTime(time, exclude, skipPlayhead)`，拖拽排除整组被拖片段，擦洗播放头排除播放头。
2. **抓取偏移用模型推**：`VisualTopOfTrack(clip.Track, _project.TrackCount) + 6` → 换成
   `block.TranslatePoint(origin, _timelineRoot)` 直接量真实块位置（量几何，不再可能不一致）。
3. **拖拽中重建时间轴**（缩放/刷新）会让块掉回泳道画布，此时写根画布坐标 → 块跳到别处；
   且浮块时 `Canvas.SetLeft/Top` 仍按旧父级解释。→ `FloatSelectedBlocks` 幂等（每次移动都调）
   + 换父级前用 TranslatePoint 换算位置。

### 体验优化

- **seek 线/标尺头拖到左右边缘自动滚动**：复用 `_dragScrollTimer`，并加 `_dragScrollFollow` 回调 ——
  指针在边缘不动时内容仍滚，用**实际**滚动量（钳制后）外推内容坐标再走一遍正常流程，
  块与播放头都不会掉队。
- **落点被自动腾到视口外时自动滚过去**：`ScrollTimelineIntoView` + `EnsureClipsVisible`
  （拖拽释放后 / 素材落放后，`Dispatcher.Post` 一帧后滚，等布局给出新范围）。
- 顺手：`DeleteTrack` 原来按 `Track == 泳道号` 删片段 → 在音频泳道上点删除会删错视频片段，
  现在按 `IsAudio/AudioTrack` 删；素材落到音频区不再凭空建视频轨；高亮与落点统一用同一套解析
  （`laneSpace`）+ 音频泳道显示名 `A1…An`。
- 去掉 `_timelineRoot` 上重复挂的 PointerMoved/Released（窗口级已覆盖，重复挂导致每事件处理两遍）。

**断言/校验口径**：泳道映射用 Python 复刻做了 3 组 V/A 组合的不变量断言（排列、视频在上音频在下、
A1 最底、中点命中、模型顶部 == 实际顶部）；构建 0 警告 0 错误；已部署（宿主未运行）。

## 「剪视频没声音」+ 分离音频 + 波形随音量变化

### 没声音：不是声卡，是音频片段 `Volume = 0`

- `VideoProject.AudioClipsAt` / `HasAudioContent` 的条件是 `!Muted && Volume > 0.0001` ——
  **音量 0% 的片段会被整条筛掉**（混音器连接都不建）。
- 证据：用户工程 `video-project.ciproj` 里那条 mp3 音频片段 `Volume: 0`（视频片段是 1）；
  `video-audio.log` 13:56 那次有 `音频源进入：SVID_...mp3`、17:46 那次**没有** →
  音量是 13:57 之后被改掉的（大概率是调着玩/看波形）；且播放器日志 17:46 停在 t=269s，
  视频片段 0..266s 已结束 → 那一段只剩被静音的 mp3 = 静音。
- 修法（让它不再像灵异事件）：检查器加了 `_audioHint`——选中片段若 `Muted` / `Volume≈0` /
  所在音频轨被静音，直接红字提示「→ 播放时听不到声音」；`ProjectAudioMixer` 启动与补建时用
  `DescribeInaudible()` 把**每个不出声的片段和原因**写进 `video-audio.log`。
- 另附给用户的自查项：Windows 音量合成器里 ClassIsland 的**单应用音量**、以及 `Volume` 字段默认值
  一直是 1（`git log -S` 确认，不是代码把默认写成 0）。

### 分离音频（检查器里的按钮）

`_detachAudioButton`（仅视频片段可见）→ `DetachAudioFromSelection()`：
新 Audio 片段（`Track=-1`、`AudioTrack` 选「同时刻放得下的已有轨，都满则新开 A(n+1)」、
复制 In/Out/SourceDuration/Volume/淡入淡出，`Muted=false`）＋ 原视频片段 `Muted=true`；
`ProbeAudioDuration` 判无音轨则提示；原音量 0% 时按 100% 分离并在状态栏说明；PushUndo ✓。
时间轴块上给静音的视频/音频片段加喇叭静音图标（`\uE816`）。

### 波形体现音量

`WaveformGainAt(clip, i, n)` = `clip.AudioGainAt(localTime)`（音量×淡入×淡出，混音器同一套）
× `AudioTrackGainOf(clip)`（音频轨静音/音量）；逐列 `clamp(peak × gain, 0, 1)` 后建几何，
整段不出声时 `visual.Opacity = 0.55`。改音量/淡入淡出/静音 → `ApplyPropertyEdits` 本来就会
`RefreshTimeline` → 块重建 → 波形按新增益重画（包络有缓存，很快）。

**校验**（模型读不了图的降级方案）：临时探针复刻缩放算法做数值断言——
音量 40% 相对 100% 线性误差 0.0000；静音全列 0；淡入淡出曲线与 `AudioGainAt` 逐列偏差 0.0000；
180% 被截断在带高内。方法已补进 skill `ui-offscreen-render-verify`（看不了图时改断言中间数组，
且验曲线要用恒定满幅假数据隔离被测函数）。
