### Issue #6 —— 动态频谱「听不见、不会跳」（根因找到并修复）

**真正的根因（此前多轮未定位）**：`AudioSpectrumCapture` 的滑动窗口计数器 `_windowCount`
在达到 `FftSize`(1024) 后被 `if (_windowCount < FftSize)` 截断，不再增长；
而「是否该做下一次 FFT」的判断用的正是 `_windowCount - _lastFftPos >= MinFreshSamples`，
于是条件在第一次成立后再也不成立 → **整个生命周期只做 1 次 FFT**，之后频谱永久静止。
用户看到的「听不见、不会跳」正是这个。

用 `tools/SpectrumProbe` 实测复现 + 验证（探针编译真实 `AudioSpectrumCapture.cs` 源码）：
- 修复前：`fftFrames=1` 恒定、`sum=0.000`、`maxLevel=0.000`（有 15 万样本流入，却零输出）
- 修复后：`fftFrames` 持续增长（2900ms 时 198 帧）、`sum≈2.75`、`maxLevel=1.000`

**修复内容**：
1. 新增单调递增的 `_windowTotal` 计数器（不受窗口容量截断），改用它判断 FFT 时机。
2. 滑动窗口取窗索引改为严格可验证的 `(oldest + i) % FftSize`（替代旧「环形缓冲 + 读完
   就地重排」写法，旧写法会把未写入区域当最旧样本、索引错位一轮）。
3. 采样解码不再假定「float32 交错双声道」：按 `WaveFormat.BitsPerSample`/`Encoding`
   分别解码 16/24/32 位与 IEEE float，并**多声道下混为单声道**（原先只取首通道）。
4. 峰值自动增益改为「快跟涨 + 极慢回落」，静音时会衰减（原先 `_peak` 只 `*0.9`，
   一次大音量后永久偏高，后续小声被压平 → 表现为「只有开头会跳」）。
5. 全套诊断日志（写入 `preview-debug.log`）：启动成功/失败原因（含设备采样率、声道、
   位深、编码）、首批数据到达、周期运行统计（已捕获样本数 / FFT 帧数 / 峰值增益 /
   瞬时最大电平，并区分「10 秒无新样本」的两类原因）。
6. `RecordingStopped` 不再静默：新增 `RecordingStopped` 事件，注入器收到后在 UI 线程
   按当前默认输出设备**自动重建捕获**（设备切换 / 音频服务重启 / 独占占用后不再永久静止）。
7. 日志通过静态 `DiagnosticSink` / `ConfigDirectoryProvider` 委托注入，使本文件不直接
   依赖宿主侧类型，`tools/SpectrumProbe` 可独立编译运行（该探针需 `TestStubs.cs` 桩）。

### Issue #8 —— 切换主界面配置方式后底色填充失效、恢复默认

**根因**：设置页的 `_splitPage` 只在 `LoadFromSettings` / 点「关闭分体主界面」按钮时刷新。
用其它方式切换配置（全局 `IsIslandSeperated`、行级 `IslandSeparationMode`）后页面仍停留在
旧语义：非分体下改画笔写的是全局值，切到分体后控件按「分块画笔」显示 → 看起来就「失效、恢复默认」。

**修复内容**：
1. `MainWindowStyleInjector` 新增静态事件 `LayoutModeChanged`，在宿主
   `Settings.IsIslandSeperated` 变化时触发（与既有 `Apply` 重应用同一路径）。
2. 设置页订阅该事件 → 立即 `RefreshSplitBlockList()`，重建分块列表并按新模式回填控件。
3. 行级分体 / 组件增删不触发全局开关，新增 800ms 低频轮询兜底（比较分体块
   `Id@LineNumber` 签名，变化才刷新；页面脱离可视树时停止）。
4. `RefreshSplitBlockList()` 增加模式翻转时的状态复位（清空选择集、`_brushActive=false`、
   丢弃待提交的画笔/底纹改动、停防抖定时器），避免旧模式状态污染新布局；
   非分体分支补上 `RefreshBackgroundTextureState()`。
5. `CommitTextureToBlocks()` 下拉取不到选中项时不再静默 fallback 到 `BackgroundTexture.Grid`
   （那等于把用户图案改成网格线 = 「恢复默认」），改为不提交该项。

### Issue #7 —— 主界面文字美化 / 文字动态反色（新功能，已实现）

新增 `TextStylingInjector.cs`（运行时可视树文字美化 + 完整还原）：
- **字体**：`TextFontFamily`（留空保持宿主原字体）
- **字号**：`TextFontSize`（0 = 保持原字号）与 `TextFontScale`（整体比例缩放）
- **字色**：`TextColorMode` = 保持宿主 / 固定色 / **跟随背景自动反色**
  （按所属区域有效背景色的相对亮度选浅色或深色字，阈值 `TextInvertThreshold` 可调；
  这正是 issue 里「浅色专辑背景变黑字、深色背景变白字」的期望效果）
- **勾边**：`TextOutlineThickness` / `TextOutlineColor`
- **作用范围**：`TextStylingMainWindowOnly`（默认只美化主界面，提醒等区域保持原样）

**关键实现细节**：
- 每个文字控件记录首次接管时的原值（字体/字号/字色/粗细/Effect），关闭功能或改回
  「保持宿主」时逐项还原，不会永久改坏宿主样式。
- 自动反色的背景色按「所在分体块优先，否则主界面底色」解析，并叠加 SMTC 动态色；
  底图铺满时返回 null（不做反色，保持原观感）。
- `RefreshDynamicColors()` 在 SMTC 动态色变化时若为自动反色模式则重新应用文字样式，
  保证取色切换背景时文字实时反色。
- **勾边实现受 Avalonia 11.3.6 API 限制**：`TextBlock` 无 `Stroke`/`StrokeThickness`
  （已核对 11.3.6 ref 程序集），且 `Effect` 只接受单个效果、无效果组类型，
  因此用 `BlurRadius=0` 的硬阴影 `DropShadowEffect` 斜向偏移模拟描边。
  若要真正的四向轮廓需等 Avalonia 支持效果组或改用自定义 `Render`。

设置页新增「文字美化」组（`SwitchableGroup`，组内按字色来源动态启停条目），
`InjectorSettingCatalog` 同步注册 12 项（供自动化设置面板使用）。
