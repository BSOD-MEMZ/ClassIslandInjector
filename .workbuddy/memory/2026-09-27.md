## 新功能：视频背景音频输出（论坛需求 / MoonPeach）

需求来源：智教联盟论坛帖 2981「这所学校最宽的普京」——用 IslandInjector 放 wide putin，请求「播放视频声音」。

**实现**（构建 0 警告 0 错误）：
- 新增 `FFmpegAudioDecoder.cs`：FFmpeg 解出音频轨 → swr 统一重采样为 **48kHz / 立体声 / s16**；支持 `Restart()` 循环复位与 `SeekTo()` 片段跳转；无音频轨返回 false 由调用方静默降级。
- 新增 `VideoAudioPlayer.cs`：NAudio **`WasapiOut`（共享模式）** + 拉模式 `IWaveProvider`——声卡要多少 PCM 就现解多少，播放节奏由声卡决定，不堆缓冲；音量走**采样缩放**（兼容性优于设备音量）；EOF 时循环则复位、不循环则补静音（返回 0 会让 WASAPI 判定流结束）。
- 设置：`VideoFillAudioEnabled`（**默认关闭**，维持「全新安装零改动」，也避免升级后突然出声）/ `VideoFillAudioVolume`（0-1，默认 1）；设置页「动态视频填充」组新增「播放声音」「音量」两项，音量滑块随开关置灰。
- 接线：`ApplyVideoFill` 单文件分支调 `ApplyVideoAudio(path)`（签名 = `路径|循环`，**仅音量变化不重启输出**；失败也记签名，避免每 50ms 重试）；切工程模式 / `RemoveVideoFill` / `Dispose` 都停音频。
- 设计取舍：音频与视频**各解各的同一文件**、互不阻塞——视频那条链路「限帧 + 等 UI 消费」的抖动不会传导到音频，否则声音会卡。音画各自从 0 起播，未做严格时钟对齐（背景视频场景够用）。

**验证（新增 `tools/AudioProbe` 探针，端到端全绿）**：
| 素材 | 结果 |
| --- | --- |
| 44.1kHz 立体声 WAV（自生成 20k 振幅正弦） | 48kHz 输出、解出 3.000s、**峰值 20000 精确吻合**、有效占比 99.83% |
| 22.05kHz 单声道 WAV | 上混正常（峰值 14142）、时长一致 |
| 真实 mp4（AAC 48kHz/182.708s） | 解出 182.592s、峰值 28667、`Restart` 与 `SeekTo(5s)` 均正常 |
| NAudio 设备输出 | `WasapiOut` 实际出声 2 秒，无异常 |

**顺带发现（重要）**：
1. 用户测试素材 `D:\Downloads\injector-video.mp4` **不含音频轨**——拿它测听不到声音，必须换带音轨的视频。
2. 插件配置目录 `ffmpeg\` 原本是**空的** → 这台机器上视频背景其实一直不可用（`FFmpegRuntime.IsAvailable=false` 会走 `RemoveVideoFill`）。已下载 8.1 精简解码包（7.5MB，含 `swresample-6.dll`）解压到该目录，音频与视频才都有依赖。

## 新功能：完整音频裁剪支持（PR 风格）

需求：编辑器要能导入音频、裁到时间轴、检查器调音量与淡入淡出、波形显示在片段里；工程文件格式按 PR 那种做（用户在选项里选了「PR 风格分层 JSON」）。

**数据模型（VideoProject.cs）**
- `VideoClip` 新增：`Kind="Audio"`、`AudioTrack`（独立于视频轨的编号，A1 = 0）、`Volume`(0–2) / `AudioFadeIn` / `AudioFadeOut` / `Muted` / `SourceDuration`；`AudioGainAt(localTime)` 给出「音量 × 淡入 × 淡出」包络（淡入淡出总长超过片段时长时按比例压缩，避免负稳态区间）。
- `TrackState` 新增 `IsAudio` / `Muted` / `Volume`；`VideoProject` 新增 `AudioTrackStates` / `AudioTrackCount` / `AudioTrackEnd` / `AudioClipsAt(t)` / `HasAudioContent` / `Assets`（素材库）/ `Name`。
- **关键约定：音频片段 `Track = -1`** —— 让所有 `c.Track == n` 的画面筛选逻辑天然忽略它，省掉几十处改动（不必逐个加 `!IsAudio`）。
- 磁盘格式 v2：`VideoProjectFile{ Version, Name, Sequence{ OutputWidth, OutputHeight, VideoTracks[], AudioTracks[] }, Clips[], Assets[] }`，扩展名 `.ciproj`；v1（`video-project.json`）读取时自动迁移，且**迁移过来的视频片段显式 `Muted=true`**（支持音频前本来就不出声，静音避免升级后突然发声）。

**混音（ProjectAudioMixer.cs）**
- 按工程时间轴调度所有出声片段（音频轨片段 + 视频片段自带原声），每片段一个 FFmpeg 解码器；10ms 小块重算活跃集合（片段边界对齐误差 ≤ 一块）。
- 音量与淡入淡出逐采样应用；各源用 int 累加、最后钳制到 s16（多轨叠加不因反复截断失真）。
- 时间基准 = 已输出采样数（声卡时钟）；每块按「应有的素材时间」校验，偏差 > 150ms 自动 `SeekTo` 纠正，所以拖动播放头不会累积跑偏。
- 由 `VideoProjectPlayer` 驱动：Start / Stop / Pause / Resume / 跳转 / 循环复位全部同步。

**波形（AudioWaveform.cs）**
- 全曲解码一遍按 20ms 细粒度记录峰值，按「路径 + 大小 + 修改时间」缓存；编辑器按实际像素宽度 `Resample` 绘制成以 0 轴为中心的对称填充。
- 提取走后台线程（长音频约 1 秒），完成后回 UI 填进 Canvas；失败只是没波形，不影响编辑。

**编辑器（VideoEditorWindow.cs）**
- 文件选择器加音频格式；音频素材不询问转码直接进素材库。
- `AddClipFromAsset` 与拖放都支持音频 → 落到音频轨（`Track=-1`）；同轨不堆叠判定走 `FitsOnAudioTrack` / `FitToAudioTrack`。
- 泳道映射：`VideoLaneCount = max(1, TrackCount)`，音频泳道紧随其后（`IsAudioLane`），视频在上、音频在下（PR 布局）；轨道头音频轨的「隐藏」按钮语义变成静音。
- 音频块内画波形（名称 + 时长 + 波形）。

**检查器**
- 新增「音频（音量 / 淡入淡出）」组：音量 0–200%、淡入秒、淡出秒、静音开关；文本 / 形状 / 滤镜片段置灰（它们没有声音）。
- 静音开关不是 Spin，单独绑 `ToggleSwitch.IsCheckedProperty`（`_propertyControls` 的循环只认 `NumericUpDown.ValueProperty`）。

**顺手修掉的既有 bug**
- `MainWindowStyleInjector` 的工程背景路径 `VideoProjectPath` **从无写入点** → `HasVideoProject()` 恒为 false，**工程背景从来没有生效过**（设置页那个「使用编辑工程」开关一直是摆设）。新增 `ResolveVideoProjectPath()` 回退到默认工程路径后修复。

**验证（`AudioProbe --project`，22 项全过）**
写出 v2 结构（Version / Sequence / VideoTracks / AudioTracks / Assets）、序列名与片段往返、音频片段音量与淡入淡出往返、`Track=-1`、`TrackCount` 只数画面片段、`AudioTrackCount` 按 AudioTrack 计算、包络五个采样点（0 / 0.75 / 1.5 / 0.75 / 0）、活跃片段判定（3s 两个 / 6s 一个 / 10.5s 零个）、v1 迁移（片段全保留 + 全静音 + 单轨拼接重排为 0 / 5 / 11 秒）。

## 修复：编辑器导入音频后完全没声音（用户实测反馈）

**现象**：编辑器里导入带音轨的视频、导入 mp3，预览播放都没声音。

**排查过程**
- `video-audio.log` 里只有导入**之前**的一条 `工程不含音频内容，不建立音频输出`，导入之后再无任何混音记录 → 说明播放时 `ProjectAudioMixer.Start` 压根没被调用。
- 用 AudioProbe 直接测用户那个 `D:\Downloads\チームメイト.wmv`：**有音轨**（wmav2 / 44100Hz / 立体声 / 266.717s，峰值满幅 32768，有效采样 97.84%）→ 素材与解码链路都没问题，问题在播放器调用时机。

**根因**：音频输出只在 `VideoProjectPlayer.Start()` 里建立**一次**。编辑器是「先按播放、后加素材」的常规顺序——起播那一刻工程里还没有音频内容，`ProjectAudioMixer.Start` 判定 `!HasAudioContent` 直接返回、`_output` 保持 null；之后再加多少素材，`UpdateProject` 只换引用、**不会补建输出** → 永远静音。

**修复**
- 新增 `ProjectAudioMixer.EnsureRunning(project, startTime)`：输出为空且工程现在有可出声内容时补建。
- `VideoProjectPlayer.RefreshClips()` 与 `Resume()` 都调用它，覆盖「运行中加素材」与「暂停后加素材再恢复」两条路径。
- 防御：`ProjectAudioMixer.AudioSource.TryCreate` / `VideoAudioPlayer.Start` 在调 FFmpeg 前显式检查 `FFmpegRuntime.IsAvailable && EnsureLoaded()` —— 否则 `DllNotFoundException` 会被 catch 吞成静音，极难排查。
- 补上素材库持久化：编辑器 `_assets` ↔ 工程 `Assets` 进出双向同步（此前 `Assets` 字段写了却从不写入，素材库每次重开都是空的）。

**教训**：凡是「只在启动时初始化一次 + 之后只更新引用」的结构，只要初始化时机可能早于内容就绪，就必须提供「按需补建」路径。这类缺陷在单次运行的探针里测不出来（探针从空到有是一次性的），必须在真实交互顺序下复现。

**证据链**
- 宿主日志 `log-2026-9-27-21-58-50`：22:13:20、22:13:36 出现 `[Control] PlatformImpl is null, couldn't handle input (PopupRoot)`；**22:14:23 之后日志戛然而止**，无正常退出记录 → 静默崩溃。

- `video-audio.log` 22:12:45 有完整的 `工程音频已启动` + `音频源进入：チームメイト.wmv` → **音频链路其实是通的**；用户报的"没声音"发生在 21:59 那次，当时工程里还没有任何可出声内容。
- `crash.log` 是 9/5 的旧内容（FluentEntranceTransition 的未观察任务异常），与本次无关。
- 排除 Issue #8 自愈嫌疑：`preview-debug.log` 里「背景装饰失效」总共只出现 4 次（其中两次是我自己的对照测试）→ 没有反复 Apply。
- Windows 事件日志在沙箱内读不到（`Get-WinEvent` 返回空）。

**成因（推断）**：`ApplyRenderedVideo` → `SaveAndApply` → `Apply()` 会让注入器新建一路解码（渲染产物 412×68），紧接着 `Close()` 释放编辑器预览播放器；而**预览播放器这时候很可能还在跑**（预览解码 + 渲染编码 + 注入器新解码三路并发），窗口关闭时的释放与新建撞在一起。

**本轮加固**
- 渲染前、以及后台渲染应用前都调用 `StopPreview()`（此前只有「添加素材」会停预览）——消除多路并发与释放竞态。
- `ApplyRenderedVideo` 前后写 `video-editor.log`（下次崩溃可直接看出卡在哪个阶段）。
- `ProjectAudioMixer` 增加 `_disposed` 标志：置位后混音线程的 `Fill` 立刻返回静音，`Stop()` 里的 `WasapiOut.Dispose()` 才等得到线程退出（否则 UI 会卡死在等音频线程上）。
- 渲染 preset `medium` → `veryfast`（编码侧小优化）。

**渲染速度的真相**：输出只有 412×68，编码本身几乎不耗时，**瓶颈是源解码**。实测 22:13:08 → 22:14:22 ≈ 74 秒 / 6400 帧 ≈ 11.6ms/帧，正是 1080p **wmv2 软解**的速度（wmv2 没有硬件解码器可用，日志里"h264_d3d11va 不可用"是另一码事）。所以渲染耗时 ≈ 源解码耗时，已接近物理下限；能动的只有**降低目标 fps**（帧数线性下降）或换硬解支持的源编码。

## 22:50 真凶找到：解码输出尺寸未按 16 对齐（推翻上面"三路并发"的推断）

**现象**：渲染完成后 ClassIsland 卡死并静默崩溃；**之后连宿主都起不来**（卡骨架屏 → 静默退出）。因为渲染产物被存成了主界面视频背景，每次启动都会去解它。

**复现（沙箱内可复现，不算 GUI 验证）**：`ClassIsland.exe`（启动器，真正进程是它拉起的 `ClassIsland.Desktop.exe`），判活**不能看进程存活**（启动器先退出），要看宿主日志里 `MemoryWatchDogService` 的 **60 秒心跳条数**。修复前 100 秒 0 条心跳 = 6 秒后崩。

**决定性对照（唯一变量 = 视频文件）**：

| 视频 | 尺寸 16 对齐 | 结果 |
| --- | --- | --- |
| `640×80`（FFmpegProbe `--enc` 软编） | ✓ | 存活 |
| `640×80`（同尺寸 qsv 硬编） | ✓ | 存活 |
| `416×80` | ✓ | 存活 |
| `412×68`（**渲染产物 injector-video.mp4**） | ✗ | **崩溃** |
| 关掉视频填充 | — | 存活 |
| `チームメイト.wmv`（1280×720） | ✓ | 存活 |

- 用 `git worktree` 构建**用户说能用的旧版 `158847f`** + 这个 mp4 → **同样崩** ⇒ 与我的改动无关，是文件本身触发的，历史版本就存在这个雷。
- `AudioProbe --vdec` 用插件自己的 `FFmpegVideoDecoder` 完整解 6401 帧 + 边界抽查 → **不崩**。（探针不崩是因为越界量小（几十字节），砸到的是 GC 段填充；在插件里同样的越界正好砸中托管对象头。）
- Windows 事件日志（沙箱里 `Get-WinEvent` 读不到，但 `wevtutil qe Application` 能读）给出：`错误模块 coreclr.dll`、`异常代码 0xc0000005` ⇒ 托管堆被写坏，不是 FFmpeg 原生崩。

**根因**：H.264 宏块 16×16。`sws_scale` 在宽度非 16 倍数时按 SIMD 粒度写目标行，而 `Open()` 里分配的目标缓冲恰好是 `_outW * _outH * 4`（`dstLinesize == _outW*4`，**行尾零余量**）→ 最后一行的越界写逃出数组、砸坏托管堆 → 之后 coreclr 访问违规，且 `try/catch` 拦不住、**一条日志都没有**。

**修复**：`FFmpegVideoDecoder.Open()` 里把 `_outW/_outH` 用 `AlignUp16()` 向上对齐到 16（`Open()` 里含 `maxDimension` 缩放之后）。修在**解码器**而非渲染侧，是为了对任意用户素材都生效。验证：用原本必崩的那个 `412×68` 文件重跑，100 秒内有心跳、稳定存活。

**保留的加固**（与真凶无关但依然正确）：渲染前/后台应用前 `StopPreview()`、`ApplyRenderedVideo` 前后写 `video-editor.log`、`ProjectAudioMixer._disposed` 标志。

**踩坑记录**
- `ClassIsland.exe` 只是启动器，判活要看 `ClassIsland.Desktop.exe` 或日志心跳（60s 一次）。
- 沙箱内起的宿主窗口在另一个桌面会话：截不到图、`EnumWindows` 也查不到 → **视觉验证只能交给用户**。
- `Get-WinEvent` 在沙箱被拒，`wevtutil qe Application /f:text` 可用。

- 用 `sed -i` 改文件会触发 autocrlf 的 LF/CRLF 警告，`git status` 显示 M 但 `git diff` 为空 —— `git update-index --refresh` 也清不掉时按"内容未变"处理即可。
