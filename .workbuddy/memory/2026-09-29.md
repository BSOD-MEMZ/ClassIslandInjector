## 「点渲染并应用 → 卡死 → 静默崩溃」= 解码器释放竞态

### 定性（不是猜的）

事件日志（`wevtutil qe Application /q:"*[System[Provider[@Name='.NET Runtime']]]"`，
沙箱里 `Get-WinEvent` 被拒但 wevtutil 可用）给出确切栈，时间与用户操作吻合：

```
Date: 2026-09-28T18:21:49  Event ID 1026
Exception Info: System.AccessViolationException: Attempted to read or write protected memory.
   at ClassIslandInjector.FFmpegVideoDecoder.ReadFrame(Byte[] ByRef)
   at ClassIslandInjector.VideoFrameSource.TryReadFrame(...)
   at ClassIslandInjector.VideoProjectPlayer.PumpTrack(TrackState, Double)
   at ClassIslandInjector.VideoProjectPlayer.Loop()
```

对照 `video-editor.log`：最后一条是 18:21:48 的预览帧日志、**没有** `渲染开始` 行
→ 说明死在 `RenderAndApply` 的第一步 `StopPreview()`，即 `VideoProjectPlayer.Dispose()`。

### 根因：Dispose 与解码线程没有互斥，且顺序反了

- `VideoProjectPlayer.Dispose()` 旧实现：先 `state.Source?.Dispose()`（直接 free native
  上下文）**再** `_worker?.Join(800)`。播放线程此刻多半正卡在 `ReadFrame` 里 → 继续读已释放的
  `AVCodecContext`/`SwsContext` → AV。`AccessViolationException` 默认抓不住，进程直接死
  （`Application Error`：模块 `coreclr.dll`、`0xc0000005`）→ 用户看到的「卡死 + 静默崩溃」。
- 这也是 `RenderAndApply` 里那句注释（"三路并发……容易踩到解码器释放竞态"）预言过的坑。

### 修法（两层）

1. `FFmpegVideoDecoder` 加互斥门 `_gate` + `_disposed`：`ReadFrame` / `SeekTo` / `Restart`
   全部走 `RunGated(...)`，`Dispose` 在门内释放（幂等）→ **在途帧读完之前不会 free**。
2. `VideoProjectPlayer.Dispose` 改成「先 `Consumed.Set()` 叫醒等待 → `Join(3000)` → 退出才释放
   解码器」；线程 3s 没退就不动解码器，交给线程自己在 `Loop` 退出路径释放（`_disposed` 判定）。

### 验证（可复现，已进仓库当回归）

临时探针用 `git show HEAD:FFmpegVideoDecoder.cs` 生成「旧版」副本做 A/B：

| | 结果 |
|---|---|
| 旧版 | `System.AccessViolationException … sws_scale → FFmpegVideoDecoderOld.ReadFrame` → SIGSEGV（退出码 139） |
| 新版 | Dispose 阻塞 ~110ms 等在途帧、读线程自然退出、释放后再读返回 false、进程存活 |

已固化为 `tools\RaceProbe`（5 轮「解码中释放」断言，退出码 0 = 安全），并写进 `agents.md` 探针清单。

**给未来的自己**：FFmpeg native 上下文（`AVCodecContext`/`SwsContext`/`AVFormatContext`）的
释放规则 = ①先停线程并 Join、②释放前与所有可能正在用它 native 调用的入口互斥。
`VideoFrameSource` / `MfVideoFrameSource` 各自 Join 自己线程的顺序是对的，出问题的是**持有者**
（播放器）在另外的线程上释放它们。

## 片段时间轴变速（Speed）+ 可选是否变调

### 模型

- `VideoClip.Speed`（0.1..8，默认 1）、`PreservePitch`（默认 false = 变速同时变调）。
- `Duration` 由 `OutPoint-InPoint` 改为 `(OutPoint-InPoint)/EffectiveSpeed` → 时间轴宽度、落位、
  `AudioGainAt` 的淡入淡出时长全部自动跟着变；入出点（素材位置）不动。
- 新增 `SourceTimeAt(localTime) = InPoint + localTime*速度`，替换所有「时间轴时间 → 素材时间」的换算：
  `VideoProjectPlayer`（三条路径）、`VideoProjectRenderer`、编辑器舞台取帧、混音器的 expectedSource。
- `ApplyTrim` 左头：时间轴位移要按速度折算（否则右缘漂移）。

### 音频：AudioSpeedReader（新文件，与 UI 无关，可单独测）

- 原速且不变调 → 直接透传（零开销）。
- 变调 → 线性插值重采样（最省 CPU）。
- 保持音调 → SOLA（30ms 窗 / 15ms 跳 / ±1ms 相关搜索，左声道隔点取样）。
  **关键**：相邻输出窗重叠 15ms，重叠段要能回改「已产出但未交付」的尾部 → 输出缓冲始终扣住
  最后 15ms（15ms 额外延迟，无感）。
- `SourceFramesConsumed` 必须报**已交付帧 × 速度**，不能报分析窗口位置：SOLA 会提前读满一窗，
  报分析位置会让调用方以为音频跑在前面 → 混音器每块都触发重定位（听感断续）。
  这一点是探针测出来的（报分析位置时 1s 输出报成消耗 2.28s）。
- 混音器 `AudioSource` 挂一个 reader；`ReadFrames`（旧的裸计数）改为只读属性转发 reader 的记账。

### 验证（探针，数值断言）

`--speed`：喂 1kHz 正弦，量输出频率与长度。

| 用例 | 输出 | 消耗素材 | 频率 |
|---|---|---|---|
| 2.0× 变调 | 1s | 2s | 2000Hz |
| 2.0× 保持音调 | 1s | 2s | **1000Hz** |
| 0.5× 保持音调 | 1s | 0.5s | 1000Hz |
| 1.5× 变调 | 1s | 1.5s | 1500Hz |
| 1.0× 原速 | 1s | 1s | 1000Hz |

### 已知限制

渲染（`VideoProjectRenderer`）**只出视频、不混音**（FFmpegVideoEncoder 无音频轨），
所以渲染产物的声音取不到 —— 变速对渲染只影响画面。
